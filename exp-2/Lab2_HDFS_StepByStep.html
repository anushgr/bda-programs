HDFS File Operations, Step by Step

Bring up a real single-node HDFS (a NameNode + a DataNode), then write, seek-read, and list files on it from Java using the Hadoop FileSystem API.

PowerShell (host)Runs on your Windows machine — Docker commands.
Inside containerPrompt looks like hadoop@namenode:~$ — Hadoop & Java.
PHASE 0

Reuse your Java image (one-time)

You already installed Java in the first program's container. Save it as an image so you never reinstall.

1Confirm Java is present, then save the image

A container is temporary; an image is a permanent snapshot. Committing bakes javac in for good.

PowerShellhost
docker exec -it hadoop javac -version
docker commit hadoop apache/hadoop:withjava
docker images
✓
Checkpoint docker images should now list both apache/hadoop 3.3.6 (original) and apache/hadoop withjava (yours, with Java).
PHASE 1

Create the lab files

2Make the lab folder
PowerShellhost
cd C:\bda_labs
mkdir lab2-hdfs
cd lab2-hdfs
3Create docker-compose.yml

This defines two containers from your Java image: one NameNode (tracks where files live) and one DataNode (stores the blocks). Both use apache/hadoop:withjava, so Java is already inside.

PowerShellhost
notepad docker-compose.yml
docker-compose.yml
services:
  namenode:
    image: apache/hadoop:withjava
    hostname: namenode
    command: ["hdfs", "namenode"]
    ports:
      - "9870:9870"
    env_file: ./config
    environment:
      ENSURE_NAMENODE_DIR: "/tmp/hadoop-root/dfs/name"
  datanode:
    image: apache/hadoop:withjava
    command: ["hdfs", "datanode"]
    env_file: ./config
4Create the config file

HDFS connection settings both containers read. Your Java program connects to the rpc-address on port 8020; replication is 1 because there's a single DataNode.

PowerShellhost
notepad config
config  — no file extension
CORE-SITE.XML_fs.default.name=hdfs://namenode
CORE-SITE.XML_fs.defaultFS=hdfs://namenode
HDFS-SITE.XML_dfs.namenode.rpc-address=namenode:8020
HDFS-SITE.XML_dfs.replication=1
⚠
No .txt extension In Notepad's Save dialog, set Save as type → All Files, or it saves as config.txt and the containers won't find it.
PHASE 2

Start HDFS

5Launch the cluster

-d runs it in the background. Wait ~15 seconds for both daemons to come up, then check.

PowerShellhost · in lab2-hdfs folder
docker compose up -d
docker compose ps
✓
Checkpoint Both namenode and datanode should show status Up.
6Create a working directory on HDFS

Enter the NameNode, then make a directory on HDFS (not on local disk). -p makes it safely even if parts exist.

PowerShellhost → enters container
docker compose exec namenode bash
containerhadoop@namenode
hdfs dfs -mkdir -p /user/student
hdfs dfs -ls /user
✓
Checkpoint The listing shows /user/student. Open http://localhost:9870 in a browser — the NameNode web UI confirms HDFS is live.
PHASE 3

Copy the program into the container

7Write HdfsDemo.java on Windows, then copy it in

The image has no nano, so the simplest path is to create the file on Windows (Notepad) in C:\bda_labs\lab2-hdfs, then copy it into the container. Run this from a second PowerShell window.

PowerShellhost
docker compose cp HdfsDemo.java namenode:/opt/hadoop/HdfsDemo.java
HdfsDemo.java
import java.net.URI;
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.FileStatus;
import org.apache.hadoop.fs.FileSystem;
import org.apache.hadoop.fs.FSDataInputStream;
import org.apache.hadoop.fs.FSDataOutputStream;
import org.apache.hadoop.fs.Path;

public class HdfsDemo {
    public static void main(String[] args) throws Exception {
        String uri = "hdfs://namenode:8020";
        Configuration conf = new Configuration();
        FileSystem fs = FileSystem.get(URI.create(uri), conf);
        Path file = new Path("/user/student/quangle.txt");

        // WRITE: create() gives an output stream (sequential only)
        FSDataOutputStream out = fs.create(file);
        out.writeBytes("On the top of the Crumpetty Tree\n");
        out.writeBytes("The Quangle Wangle sat\n");
        out.close();
        System.out.println("Wrote file: " + file);

        // READ + SEEK: open() gives a seekable stream
        FSDataInputStream in = fs.open(file);
        byte[] buffer = new byte[32];
        in.read(buffer);
        System.out.println("From start : " + new String(buffer).trim());
        in.seek(33);                     // jump to absolute byte 33
        byte[] buf2 = new byte[32];
        in.read(buf2);
        System.out.println("After seek : " + new String(buf2).trim());
        in.close();

        // METADATA: getFileStatus
        FileStatus st = fs.getFileStatus(file);
        System.out.println("Length     : " + st.getLen() + " bytes");
        System.out.println("Replication: " + st.getReplication());

        // LIST: listStatus on a directory
        System.out.println("--- listStatus /user/student ---");
        for (FileStatus s : fs.listStatus(new Path("/user/student"))) {
            System.out.println("  " + s.getPath().getName());
        }

        // GLOB: wildcard matching
        System.out.println("--- globStatus *.txt ---");
        for (FileStatus s : fs.globStatus(new Path("/user/student/*.txt"))) {
            System.out.println("  " + s.getPath().getName());
        }
        fs.close();
    }
}
PHASE 4

Compile, package, and run

8Go to the file's folder — then verify it's there

This is the exact spot that caused the earlier ClassNotFoundException: you must compile in the same directory as the file. You copied it to /opt/hadoop, so go there first.

containerhadoop@namenode
cd /opt/hadoop
ls -l HdfsDemo.java     # confirm the file is here
9Clean build the JAR

rm -rf classes clears any leftover .class files from the first program — that's what stops the old WordCount classes from sneaking into this jar. $(hadoop classpath) supplies the Hadoop libraries the code imports.

containerhadoop@namenode
rm -rf classes hdfsdemo.jar
export HADOOP_CLASSPATH=$(hadoop classpath)
mkdir classes
javac -classpath $HADOOP_CLASSPATH -d classes HdfsDemo.java
ls -l classes/          # MUST show HdfsDemo.class
jar -cvf hdfsdemo.jar -C classes .
jar -tf hdfsdemo.jar    # MUST show HdfsDemo.class, not WordCount
⚠
Check both listings before running If ls classes/ or jar -tf shows WordCount.class (or nothing), the compile didn't take — fix that before the next step, or you'll get ClassNotFoundException: HdfsDemo again.
10Run the program
containerhadoop@namenode
hadoop jar hdfsdemo.jar HdfsDemo
Expected output 
Wrote file: /user/student/quangle.txt
From start : On the top of the Crumpetty Tree
After seek : The Quangle Wangle sat
Length     : 56 bytes
Replication: 1
--- listStatus /user/student ---
  quangle.txt
--- globStatus *.txt ---
  quangle.txt
11Confirm the file really lives on HDFS

The “After seek” line printed the second line of the file — seek(33) jumped straight to byte 33 in one opened stream. That is HDFS's seekable random-access read, the whole point of the lab.

containerhadoop@namenode
hdfs dfs -cat /user/student/quangle.txt
PHASE 5

Test the glob with a second file

12Add a file from the CLI, then re-run

You add notes.txt from the command line; the Java program sees it immediately. Now listStatus and globStatus list both files. Re-running is safe because create() overwrites.

containerhadoop@namenode
echo "hello hdfs" | hdfs dfs -put - /user/student/notes.txt
hadoop jar hdfsdemo.jar HdfsDemo
PHASE 6

Clean up

13Exit and tear down

docker compose down stops and removes both containers in one command.

containerhadoop@namenode
exit
PowerShellhost
docker compose down
⚠
Data is not persistent This setup has no volume, so down wipes the HDFS data. On a future run, redo Step 6 (hdfs dfs -mkdir -p /user/student) before the program will work.
